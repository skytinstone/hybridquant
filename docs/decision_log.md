# 결정 로그

결정을 번복할 때는 이전 줄을 지우지 않고 아래에 새 줄을 추가합니다.

- 2026-10-13 연구 주제를 하이브리드 LLM의 KV cache + recurrent state 공동 양자화(비트 배분)로 정했습니다. 이유: 선형 어텐션 state 양자화 논문이 2026.08~09에 4편 나왔지만 모두 state만 다루고 joint allocation은 없습니다. dLLM/VLA/MLA 양자화는 이미 선점된 주제입니다.
- 2026-10-13 주력 모델은 Qwen3.5 0.8B/2B/4B/9B이고, 2차 아키텍처로 Falcon-H1(Mamba-2 하이브리드) 0.5B~3B를 추가할 예정입니다. 이유: GDN(delta rule)과 Mamba-2(decay only)에서 같은 경향이 나와야 일반화를 주장할 수 있습니다.
- 2026-10-13 양자화 개입 지점은 transformers 캐시 클래스의 쓰기 메서드(DynamicLayer.update, LinearAttentionLayer.update_recurrent_state)입니다. 이유: 모델 코드를 수정하지 않고, 커널과 무관하며, 모든 하이브리드 모델에 똑같이 적용됩니다.
- 2026-10-13 state 양자화 의미론은 "저장 시점 양자화"입니다. prefill 중간 state는 full precision이고 최종 state만 양자화하며, decode 중에는 매 토큰 양자화합니다. 따라서 1차 지표는 teacher-forced decode NLL입니다. 단순 forward PPL로는 state 효과가 보이지 않습니다.
- 2026-10-13 v1 양자화 포맷: K/V는 per-token asymmetric group(128) INT이고, state는 d_v 축 group(128) asymmetric INT에 stochastic rounding 옵션을 둡니다. KIVI식 per-channel key는 v2에서 다룹니다.
- 2026-10-13 속도는 측정하지 않고 fake-quant만 합니다. 이유: Colab 단독 환경이고 커스텀 커널을 쓰지 않습니다.
- 2026-10-13 hooks.py의 state 훅에서 state_calls / layers_seen_state 카운터를 양자화가 꺼져 있을 때(bits>=16)도 올리도록 바꿨습니다(KV 훅과 동일). 이유: fp 베이스라인에서 QuantStats로 훅 발화 여부를 확인해야 하는데(M1 항목 1), 기존 코드는 state_calls=0을 내놓아 훅이 안 불린 것처럼 보였습니다. 양자화 자체는 여전히 enabled일 때만 적용됩니다.
- 2026-10-13 M1 로컬 검증 결과입니다. transformers 5.19.0.dev0(git main) 기준으로 DynamicLayer.update(k, v, *args, **kwargs)와 LinearAttentionLayer.update_recurrent_state(s, state_idx=0, **kwargs) 시그니처가 패치 함수와 일치합니다. Qwen3_5GatedDeltaNet.forward와 Qwen3_5Attention.forward는 각각 Cache.update_recurrent_state / Cache.update를 거쳐 레이어 클래스 메서드를 부르므로 클래스 패치가 항상 경로에 있습니다. DynamicCache(config)는 layer_types 순서대로 LinearAttentionLayer / DynamicLayer를 만들므로 tag_cache_layers의 enumerate 인덱스가 decoder layer_idx와 일치합니다.
- 2026-10-13 kernels 허브 우회 위험을 확인했습니다. Qwen3_5GatedDeltaNet은 use_kernel_forward_from_hub로 장식돼 있어, kernelize()가 forward를 통째로 바꾸면 cache.update_recurrent_state 호출이 사라지고 state 훅이 조용히 건너뛰어집니다. 설치된 소스 기준으로 이 교체는 from_pretrained(use_kernels=True), kernel_config 전달, model.use_kernels=True일 때만 일어나고 기본값은 False입니다. 대응: scripts/check_hooks.py가 QuantStats를 layer_types와 대조해 PASS/FAIL을 판정하고, FAIL이면 --no-hub-kernels(transformers import 전 USE_HUB_KERNELS=NO + use_kernels=False)로 다시 실행합니다. 기본 매핑의 GDN 레이어 커널은 CUDA capability 121(GB10)과 ROCm 115에만 걸려 있어 L4/A100에서는 기본적으로 교체되지 않지만, 실험 전에 매번 check_hooks로 확인합니다.
